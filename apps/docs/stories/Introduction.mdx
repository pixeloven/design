# PixelOven Design System

One source of truth for the brand: tokens, marks, and the rules that keep them
one family.

## Why it exists

The palette used to live in two independently maintained copies — Harmony's
Homepage stylesheet and Lattice's `globals.css`. Measured before any of this was
built:

None of it was noticed by looking. All of it is now asserted by tests.

At the initial audit, the parent brand site ran `#ff5722` while every product ran `#7c3cff`
— the company and the things it shipped looked like unrelated businesses.

## Consuming it

**With a bundler:**

```ts
import tokens from "@pixeloven/tokens";
import "@pixeloven/tokens/tokens.css";
```

**Without one** — a mounted stylesheet, a Kubernetes ConfigMap, a static page:
vendor `dist/tokens.css` at a pinned release. Add a consumer CI check that diffs
the copy against that release. Use the pinned dark or light stylesheet when
the surface intentionally supports only one appearance. This is an integration
contract; it does not imply every consumer has completed adoption.

## What is enforced, not just documented

A design system that only asks nicely becomes a fourth copy. These are CI gates:

- the **elevation ladder** moves monotonically away from the page ground, in
  both schemes
- no two adjacent steps are **imperceptibly close** (≥3 in RGB)
- every text colour clears **4.5:1 on the ground it declares**
- the two schemes stay **perceptually equivalent** — each step sits the same
  distance from its own ground in both
- every colour token **defines every scheme**
- marks use **only design-system colours**
- migrated consumers contain **no literal hex and no bare RGB triplet**

Each guard was verified to *fail* against a real mistake before being trusted.
A check that has never failed is not a check.

## Current direction

Published foundations include Cool/Warm themes, Acid/electric Violet accents,
independent light/dark/system appearance, readable typography and the approved
Solid/Inset identities. The Themes and Marks pages use these production sources.

Lattice's accepted redesign uses the shared foundations and controls. Warden's
issue-workflow MVP and foundation adoption have merged in
[#80](https://github.com/pixeloven/warden/pull/80) and
[#81](https://github.com/pixeloven/warden/pull/81). Warden pins brand 0.3.0,
tokens 0.6.0 and UI 0.1.0, with the selected Waymark Solid header, Inset icons,
shared native controls and all eight theme combinations. System remains its
default appearance, with Cool + Acid. The owned workflow and desktop/phone
viewport checks passed; no customer deployment or migration occurred.
**Studies / Warden** contains the synthetic workspace study and unselected
historical alternatives alongside the selected Waymark. Its preview does not
connect to the product or establish a customer deployment. See the
[implementation handoff](https://github.com/pixeloven/warden/blob/fa4e3369081cc90490e31805547658f0b928925b/docs/mvp-handoff.md)
for the validated source and remaining cutover work.

See the [brand-family guide](https://github.com/pixeloven/design/blob/main/docs/brand-family.md)
for the agreed direction and [design #8](https://github.com/pixeloven/design/issues/8)
for the closeout sequence. Harmony's Homepage already links to this design site.
Publishing these docs and refreshing the deployed Storybook image complete the
remaining design-session work; the deployed stories still require browser
verification after that refresh.
