# Brand themes

Cool and Warm share the same control behavior and readable type. Acid and
electric Violet are independent accents. Appearance chooses Dark, Light, or
System; it does not choose a visual theme or change task state.

<Canvas of={Themes.SharedWorkflows} />

## Opt in

Existing token imports retain their values. Import the theme layer after the
legacy stylesheet and choose a visual theme on the document root:

```ts
import "@pixeloven/tokens/tokens.css"
import "@pixeloven/tokens/themes.css"
```

```html
<html data-pxo-theme="cool" data-pxo-accent="violet" data-theme="dark">
```

Remove `data-theme` to follow the OS. Explicit `dark` and `light` override the OS.
Without a valid `data-pxo-theme`, importing the theme layer changes nothing.

For rendering a canvas or an isolated specimen, use the same roles through
`resolveTheme(settings, systemScheme)` from `@pixeloven/tokens/themes`.
The result includes the resolved `scheme` and a complete `tokens` object.
`normalizeThemeSettings` validates untrusted saved preferences. These helpers
are pure: the consumer owns browser storage, OS subscriptions and DOM updates.

## Role boundaries

Use `actionPrimary`, `actionPrimaryHover`, `actionPrimaryPressed` and
`actionOnPrimary` together for primary controls. `accentText` is for links and
text emphasis; a bright button fill is not necessarily legible as text.
`borderControl` distinguishes an essential control boundary from a decorative
divider. `interactionFocus` and the paired selection surface/text roles carry
keyboard and selected states.

Status colors retain meaning. Graph origins retain their own color and pattern
roles. Brand marks retain their neutral ink. An accent change must not recolor
every object in the application.

## Adoption

Pin the published package and update the consumer deliberately. Lattice must
retain its existing saved appearance and Dark fallback during migration; the
new helper's defaults are not a migration policy. Handle unavailable storage
without preventing use, and keep active queries, notes and tasks when a setting
changes. Production 3D graph rendering needs its own validation.

The examples above import `Button`, `Input`, `Select` and `Label` from
`@pixeloven/ui`, including its shipped stylesheet. The surrounding task flows
use sample data; the controls are the same package consumers install.

```tsx
import { Button, Input, Label, Select } from "@pixeloven/ui"
import "@pixeloven/ui/styles.css"

<Label htmlFor="query">Find a note</Label>
<Input id="query" name="query" type="search" />
<Button variant="primary" type="submit">Search</Button>
```

Buttons default to `type="button"`; forms opt into submission. Inputs and selects
keep their native label, validation, keyboard and form behavior. Pass
`aria-invalid` with `aria-describedby` for an error and its explanation. Consumers
own labels, validation messages, application state and font loading.
